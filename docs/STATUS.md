# Status

*Last updated: 2026-10-31, session 2. Read this first when resuming.*

## Summary

Session 1 did Phase 0 and the Phase 1 spikes (**GO for M1**, `docs/PHASE1_REPORT.md`).
Session 2 delivered the core of **M1 (interactive sketching)** and **M2 (Extrude, Fillet,
timeline editing, parameters)** in the desktop app, an original **icon set** for every
tool, build-from-source support for **Void, Fedora, Arch and openSUSE**, and a publish job
for downloadable builds, then Chamfer and Shell (part of M3) with the pen cup sample,
then Revolve, Hole, rectangular and circular Patterns and Mirror with panels, Arc/Slot/
Polygon sketch tools, and **Text** (FreeType outlines, built-in Inter font, D-014), which
completes the knob (A2) and pen cup (A3) samples including their lettering, and the
Inspect tools **Measure** and **Properties**, **3MF** export, **construction planes**
(offset, at an angle, midplane), **Combine, Split body and Move/Copy**, and **Section view**.
79 test entries (78 core tests plus the UI workflow suite, which drives the real window in 11 scenarios); all of them, UI tests
included, also pass under AddressSanitizer + UBSan (leak checking on for the core).

**Latest (session 2, end):** dark theme is the default (Light and High contrast in Edit ▸
Settings); designs have a unit (mm, cm, m, in, ft) chosen per design and for new designs;
in an inch design plain numbers mean inches and every size, area and volume (and weight in
ounces) is shown in inches. The owner's standing instruction is in `CLAUDE.md`.

- Fixed (2026-11-01, found by reading the code while chasing a rare `boxSelectBodies` failure): when the bodies of one update finished meshing in different frames, each frame's first result cleared the view again, so bodies meshed earlier could vanish until the next change. The view now remembers which update its meshes belong to. No test forces the meshes apart (they usually finish in one frame); the UI test now shows its bodies explicitly and waits for both meshes, and the full suite passed after the change.
- Fixed (2026-11-01, CI run 140 on macOS Intel): trimming an ellipse or smooth curve with a line through one of its sample points could miss the crossing or count it twice, depending on how the platform rounds (there, cos(π/2)), so a half ellipse closed by a line found no area. Crossings within 1e-9 of a sample point now count once. `SketchTrim.EllipsesAndSmoothCurves` repeats the case with the line nudged by ±1e-15 to ±1e-11; without the fix a nudged case fails here on Linux the same way.
- AppImage packaging (2026-11-01): the continuous appimagetool build now insists on a PNG icon for `.DirIcon`; a 256 px PNG rendered from the SVG is shipped (CI run 139 failed on this).
- Bug hunt (2026-11-01, owner's request), first pass:
  - The whole app built with AddressSanitizer + UndefinedBehaviorSanitizer and every test run under it, the UI tests included (before, only the core was): no memory errors or undefined behaviour found.
  - Fixed: a damaged file whose sketch curve named a point that was not there **crashed** the solver (null pointer; reproduced under ASan). Sketches are now checked when read and refused with an explanation (`Solver.MalformedJsonIsRejectedNotCrashing`: every curve field of a line, circle, arc, ellipse and smooth curve pointed at a missing id or at a curve).
  - Fixed: a damaged linked copy (a pattern count that is not a number) threw out of the sketch solver, which the sketch editor does not catch; such a copy now stops following its source. Links with lists that are not numbers, or that list their own source as a copy, are refused when read.
  - Fixed: a grid copy multiplied its two counts in 32 bits, so two huge counts could wrap past the 400-copy limit.
  - Fixed: a script line with a word where a number belongs (`reorder e1 to=abc`) **aborted the program**; every line now reports such values as that line's error (`Commands.ScriptErrorsNameTheLine`).
  - Fixed: DXF group codes such as `-` or eleven digits, and a units value that is not a number, could throw; now refused or ignored (`DxfImport.InchDrawing…`).
  - Hardened: previews and autosave wait while a rebuild runs on the worker thread.
- Bug hunt, second pass:
  - A structured fuzzer (`Document.DamagedDesignsNeverCrash`): the three samples and a sketch with an ellipse, a smooth curve and text, damaged inside valid JSON (wrong kinds of value, huge and negative numbers, ids pointing elsewhere, missing keys), opened and rebuilt; 60 rounds each in the suite, 250 each run once under ASan + UBSan (1000 designs): no crash. UBSan found one signed overflow: an id of 2147483647 made the next id overflow. Ids are now limited to 1 to 10⁹ when read, and the document's id counters are clamped.
  - Fixed, **crash**: deleting a point that a line used as an end (possible with points shared between curves) left the line pointing at nothing; the next solve crashed. Deleting a point now deletes the curves built on it, in the core (`Solver.DeletingAPointTakesTheCurvesBuiltOnIt`).
  - Fixed: deleting one point of a smooth curve in the sketch editor left the curve listing the deleted point (it was drawn through 0,0). The curve now just no longer passes through it, and goes only when fewer than two points would remain (UI test `deleteSmoothCurvePoint`, which fails on the old code).
  - About 60 degenerate script inputs (zero and negative sizes, 100000-sided polygons and copies, 1e300 values, zero angles, duplicate points, …) run one by one: no crash, hang or NaN. Lengths over 10 km are now refused with a reason instead of failing deep inside the kernel.
